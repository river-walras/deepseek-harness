# Agent Note: 零配置根同级协作

Status: proposed

[English](2026-08-15-zero-setup-root-peer-collaboration.md) | 中文

## 问题

实时根会话需要横向发现和消息投递，不能依赖对话外的人类协调。[人类组建组的提案](../../rejected/feature/2026-08-14-cross-session-peer-collaboration.md)让发现依赖预先存在的成员资格：`list_peers` 列出组成员，因此在人类创建组并添加会话之前，模型看不到任何同级。实时测试表明，这个前置条件会破坏该能力的常规使用。

subagent 祖先关系不能提供横向权限，因为子节点有所有者且不是根。同时，让每个实时根都可寻址必须公开工作区冲突、保留命令归因，并阻止标题重命名重定向进行中的等待。

## 提案

以 `ctx.peers` 取代 `ctx.peerGroups`。进程中的每个实时根无需成员资格状态、命令、授权或成员移除事件即可相互发现和寻址。subagent 子节点仅因不是根而继续被排除。该关系仅限进程内，不声称在根之间提供租户隔离。

`list_peers` 将返回其他所有实时根。会话 id 将作为规范地址。精确的当前用户设置标题在唯一标识另一个根时也可解析；自动标题仍仅用于显示，重复用户标题将以 `AMBIGUOUS_PEER` 失败。解析将优先使用会话 id、拒绝自寻址，并且每项操作只执行一次。

`send_to_peer` 将在副作用前立即重新验证两个精确实时根。共享提供方不透明规范工作区身份的两个可写根会在列表和消息受理上获得 `sharesWritableWorkspace` 提示；投递仍会继续，因为同工作区协作是常规用途。当前人类沙箱和审批策略将决定分类，无需策略监听器或持久成员资格事件。

提供方将在普通投递前同步解析每段文本。命名目标 Agent 已组装命令的斜杠文本会分派到该根的命令平面，且不创建收件箱消息。分派会立即返回目标会话与命令名称，不等待处理器结果；被拒绝的执行会被记录并吞掉。省略 `dispatchableCommands` 会开放全部已组装命令，因此任一实时根都能在其他任一实时根中启动任意命令，包括 `/permission` 和 `/compact`，与人类在该会话中键入命令时一致。部署可以把 `dispatchableCommands` 设为不带斜杠的命令名称，以收窄这项权限。`command/run` 会用 `source.kind = 'peer'` 将执行归因于发送会话；无法识别或被排除的斜杠文本仍作为普通消息投递。

等待将保留 Agent-wait 游标协议和有界配置。每项等待都会固定已解析的目标 Agent 对象，并安装一条进程范围内经过环路检查的边。后续标题重命名不会重定向等待；目标替换、任一 Agent dispose、中止、超时、订阅失败和提供方 dispose 都会结算并清理等待。

同级投递仍将是带归因的普通 `Agent.followup()` 消息。目标消息来源会保留发送方会话和投递身份用于重建，但绝不作为权限。

## 考虑过的替代方案

**保留组但自动加入根。** 否决，因为通用隐式组会保留成员资格概念、命令与事件机制以及组限定身份，却不再限制发现或权限。

**允许自动标题作为地址。** 否决，因为自动生成可能与操作竞态，并产生用户未选择为稳定引用的重复显示标签。

**在等待期间持续解析标题。** 否决，因为重命名可能把活动等待转移到另一个 Agent。只解析一次并固定对象身份，可保留操作开始时选定的目标。

**拒绝同工作区投递。** 否决，因为两个根在一个 checkout 中工作是常规协作场景。报告 `sharesWritableWorkspace` 会保留冲突事实，同时让调用方掌握委派策略。

**把所有斜杠文本作为普通消息投递。** 否决，因为同级根将无法访问人类可用的直接会话控制。目标作用域命令查找保留目标已组装的命令集合，`dispatchableCommands` 提供部署限制。

**返回命令处理器结果。** 否决，因为处理器结算可能耗时数十秒，并会让分派延迟与目标工作耦合。准入失败仍保持同步，因为它属于发送方事务；执行结果属于目标 transcript，可选等待只观察目标状态。

## 验收标准

- Service Definition、进程内 Provider、工具 Consumer、组合、目录和文档使用 `ctx.peers` 与 `packages/peer/` 系列；同级成员资格命令和事件不存在。
- 两个实时根无需配置即可相互发现；子 Agent 因不是根而不在列表中。
- 聚焦覆盖会话 id 寻址、唯一用户标题寻址、重复标题歧义、排除自动标题、自寻址拒绝、重命名安全等待和目标替换。
- 发送时测试覆盖当前调用方与目标存活性、人类交互阻塞、同级等待期间投递，以及当前策略下的同工作区冲突提示。
- 已识别的同级命令会在慢处理器结算前返回，不经收件箱投递而记录同级归因，包含后续拒绝，支持仅状态等待，并对未知或被允许列表排除的名称回退到消息投递。
- 无密钥 snapshot 脚手架物化两个根，通过 `session.rename` 重命名其中一个，再按标题列出和发送；录制仍是独立的真实模型操作。
- 生成的 Cordis、工具、图、持久化和组合目录不包含成员移除事件或 peer-group 包。

## 风险

根身份是一种宽泛权限关系，默认包括另一个根已组装的命令。在同一进程托管互不信任用户的部署必须增加更强的所有权边界，不能依赖此提供方；信任各根但希望减少跨根命令的部署可以设置 `dispatchableCommands`。

用户标题歧义可能在成功列出后、后续发送前出现。每项操作都会按最新解析安全失败；标题冲突时调用方可以使用会话 id。

进程内发现不会恢复冷会话，也不会协调跨进程写入者。这些能力需要独立的激活和权限机制。
