# @deepseek-ai/dsh-peer-local

[English](README.md) | 中文

[`@deepseek-ai/dsh-peer`](../peer/README.md) 的进程内 Service Provider。它安装 `ctx.peers`，从 Agent 注册表发现当前根、折叠持久标题、解析 preset 标签、依据不透明的规范工作区身份分类当前写入权限、投递后续消息并维护进程范围的等待图。

只有用户来源标题可作为地址。解析顺序先是会话 id，再是精确用户标题匹配；零匹配以 `PEER_NOT_FOUND` 失败，多匹配以 `AMBIGUOUS_PEER` 失败，调用方自身以 `SELF_PEER` 失败。等待会固定已解析的 Agent 对象，因此后续标题重命名不会重定向等待，而该会话的根被替换时会以 `PEER_REPLACED` 结束。

共享可写工作区只作报告，不作强制。当调用方与该同级都对同一个规范工作区持有写入权限、并发编辑会相互冲突时，`list()` 与 `send()` 会标记 `sharesWritableWorkspace`；投递照常进行，由模型决定要委派什么。两侧的分类都在每次调用时依据当前沙箱与审批状态得出，因此权限变更无需成员资格或策略事件订阅即可生效。发送拒绝 `interaction`、允许 `peer`，并在副作用前立即重新验证两个实时根。

已归档的会话仍保留其 Agent，因为归档只隐藏侧栏行。提供方因此将工作区注册表的归档集合排除在发现之外并拒绝寻址，而不是唤醒人类已收起的工作。未组装工作区注册表时，不存在已归档会话。

在投递跨越异步步骤之前，提供方会同步解析文本，并根据为目标 Agent 组装的命令进行解析。已识别命令通过 `ctx.commands.execute()` 运行并携带同级归因，不产生收件箱消息。省略 `dispatchableCommands` 会开放全部已组装命令，包括 `/permission` 和 `/compact`，使任一实时根对另一个实时根拥有与人类在其中键入命令相同的命令访问权。将 `dispatchableCommands` 设为不带前导斜杠的名称列表可以收窄该访问权；被排除或未知的斜杠文本仍作为普通消息投递。

`defaultWaitTimeoutMs` 和 `maxWaitTimeoutMs` 是必填的正整数 Cordis 配置字段，没有隐式部署值；默认值不得大于最大值。`resolveWait()` 将状态集合默认为 `idle | blocked`，应用配置默认值，并限制显式毫秒数。

执行观察遵循 Agent-wait 游标协议：获取快照、从游标后订阅、排空保留的转换，并且仅在 `epoch-changed` 或 `revision-gap` 后替换投影。命令不创建消息轮次，因此命令执行后的等待只基于状态。等待清理覆盖匹配、中止、超时、调用方或目标 dispose、目标替换、订阅失败和提供方 dispose。

## 模型体验

### 进程内同级 Agent 协调

#### 模型看到什么

不会直接看到来自 `ctx.peers` 的内容；工具消费方拥有模型可见 schema 和结果。

#### Token 影响

直接 token 为零；发现和等待边都是运行时状态。

#### KV Cache 影响

不会直接失效；提供方不组装模型请求。

## 已知限制与延期工作

- **不包含冷会话** — 投递和等待仅操作当前进程中的活动根。
- **规范工作区身份仅限提供方本地** — 跨进程写入协调需要另一种权限机制。
